## 6. 検証で分かった限界

### RAGはVaultを丸ごと読む仕組みではない

Vault QAは、質問と意味が近い断片を上位から数個拾う。ノート全体や正本の優先順位を、人間と同じように理解するとは限らない。

### 新旧や重要度を自動では判定できない

過去テストでは、8月の予定を尋ねた際、古い計画から「SNS毎日100件・NPO設立」などを現在方針のように回答した。正しい現在地は、📌事実と前提、🔭検討中プロジェクト、🗒相談ログの最新決定を優先する。

### 小型・ローカルモデルは拾った断片から作文しやすい

流暢さを根拠と考えない。資料にない数字、出典、製品、価格、出来事を補わせない。確認できない場合は停止させる。

2026-07-16の境界テストで、Qwen3.6は「メガリザードンXex」の相場は確認できないと停止した一方、存在自体は「安定した一般知識」として断定。根拠を求められると、2014年Phantom Forces、日本版「黒き炎のドラゴン」、53/108という詳細を捏造した。公式確認では、現在の「メガリザードンXex」は実在するが、日本公式登録は`M2a 223/193`・「MEGAドリームex」。Phantom Forces公式リストにリザードはなく、番号53はPoochyena。つまり存在は偶然当たったが、根拠と詳細は捏造。

再発防止として、`.obsidian/plugins/copilot/data.json`の共通`userSystemPrompt`と`/ynp97`の両方に、①モデル内部の学習記憶は固有対象の検証済み根拠ではない、②実際の参照文脈なしに「公式で確認」と言わない、③根拠を示せなければ前回の断定を撤回して終了、④似た名称・新旧表記を置換しない、を追加した。

### LM StudioアプリのSystem PromptとCopilotは別入口

LM Studioアプリのチャット欄で設定したSystem Promptが、CopilotからAPI経由で呼ぶ回答へ自動適用されるとは限らない。そのため、Copilot側の `/ynp97` にも捏造防止ルールを記載している。

### 最新情報・ネット検索は別系統

ローカルQwen単体は現在の相場・ニュース・発売情報などをリアルタイム確認できない。Vault内資料の整理・要約・検索・下書きと、ネット確認が必要な仕事を分ける。

## 9.5 安価APIとの比較検討（2026-07-18・検証は明日）

> [!important] ローカルAIを選んだ動機は「値段」であって機密ではない（本人確認 2026-07-18）
> AIが「機密のためにローカル」と書いていたのは推測であり誤り。**動機は費用**。したがって、十分安いフロンティアAPIが出た場合、ローカルという手段は目的（費用を気にせずVaultを読ませる）に対して見直しの対象になる。CLAUDE.mdの原則「本来の目的へ戻る／手段を目的化しない」の適用対象。

- **比較対象**: `OpenClaw`（エージェント型ツール、OpenAI互換API）＋ **DeepSeek V4 Pro**。設定は baseUrl `https://api.deepseek.com/v1`、モデル名 `deepseek-v4-pro` / `deepseek-v4-flash`。
- **価格（2026-07-18確認）**: DeepSeek V4 Pro＝入力 **$0.43/M**・出力 **$0.87/M**。Claude Opus 4.8＝入力 $5.00/M・出力 $25.00/M。**入力で約11.6倍、出力で約28.7倍の差**。入力50万＋出力10万トークンのセッションなら、DeepSeek約$0.30（約45円）／Opus約$5.00（約750円）。従量課金なので使わなければゼロ。
- **DeepSeek V4 Proのスペック**: 2026年4月リリース。SWE-bench Verified 80.6%。MoE（総1.6T／アクティブ約49B）、コンテキスト100万トークン。2026年5月に75%値下げが恒久化。
- **★重要な制約：画像は非対応（2026-07-18確認）**: **公開APIはテキスト専用**。visionはチャット画面（chat.deepseek.com）限定で、APIドキュメントに画像コンテンツタイプもvisionエンドポイントも無い。2026-04-30に「Thinking with Visual Primitives」の技術レポートはあるが、一般提供のAPIではない。→ **レコード査定など「スクリプトから大量の写真を回す」用途には現時点で使えない**。今後API対応する可能性はあるので、組む前に再確認すること。
- **結論としての役割分担（能力と経済性にもとづく／機密が理由ではない）**:
  - **テキスト・コード・推論の下働き** → 安価API（DeepSeek等）。重い開発作業をここへ逃がせば、週間使用量の圧が戦略相談側から減る。
  - **大量の画像処理（レコード査定・出品写真）** → **ローカルのQwen3-VLが依然有利**。1枚ごとの課金が乗らない限界費用ゼロが効く。三層設計（バーコード/OCRで一次仕分け、重いAIは難物だけ）と整合。

## 9.6 OpenClaw（DS）を画像対応にする＝Qwen3-VLへセッション内切替（2026-07-21 成立・実画面確認）

OpenClawの既定モデル `deepseek-v4-flash` はテキスト専用で画像を見られない。スクショを見せて相談したいとき（例: FCP操作を教わる）は、**同一セッション内でローカルのQwen3-VLへ切り替える**。DeepSeek（クラウド）は画像時もVRAMを使わないので、テキスト＝DeepSeek／画像＝ローカルVLの二枚看板が両立する。

**前提**: LM Studioに `Qwen3 VL 30B A3B Instruct`（`qwen3_vl_moe`, MLX, 約17GB）がダウンロード済み（確認 2026-07-21）。

**設定（`~/.openclaw/openclaw.json`）**: DeepSeekは触らず、LM Studioプロバイダを追加するだけ。純正バックアップ（`openclaw.json.bak` 等）も自動で残る。
- `models.providers` に `lmstudio` を追加：`baseUrl: http://localhost:1234/v1` ／ `apiKey: "lmstudio"`（ダミー・ローカルは認証なし）／ `api: "openai-completions"` ／ `params.preload: false`（LM StudioのJIT/手動ロードに任せる）／ モデル `id: "qwen3-vl-30b-a3b-instruct-mlx"`、`input: ["text","image"]`、`contextWindow: 32768`。
- `agents.defaults.models` に `"lmstudio/qwen3-vl-30b-a3b-instruct-mlx": { "alias": "Qwen3-VL" }` を追加。`model.primary` はDeepSeekのまま。
- モデルの正確な`id`は `curl http://localhost:1234/api/v1/models` の `"key"` で確認できる（今回は `qwen3-vl-30b-a3b-instruct-mlx`）。書式の正本は [OpenClaw LM Studio doc](https://docs.openclaw.ai/providers/lmstudio)。

**使う手順（毎回）**:
1. LM Studioで `Qwen3 VL 30B A3B Instruct` をLoad。`preload:false`なので**手動ロードが確実**。ロード時の **Context Length は 16384〜32768**（画像1枚は約1〜2千トークン。数枚でも十分）。「Remember settings for …」にチェックしておくと次回自動。
2. **32GBメモリでは最大コンテキスト（262144）は不可**。本体17GB＋巨大KVキャッシュで溢れる。16384（他アプリ併用時）〜32768が安全圏。もっと長くしたいときだけ `KV Cache Quantization` をON。
3. OpenClawで**新しいセッション**を作る（画像は履歴を食うので使い回さない）。左下のモデルを **Qwen3-VL** に切替。**スクショは1枚ずつ**貼って質問。
4. 画像用が済んだらテキストはDeepSeekへ戻す。

**つまずきの正体（2026-07-21）**: 最初に失敗したのは「未ロード」が主因（LM Studioが `Select a model to load` のままだった）。コンテキスト長不足ではなかった。以後は「まずLM Studioで実際にロードされたか（モデル名が表示されるか）」を最初に確認する。
