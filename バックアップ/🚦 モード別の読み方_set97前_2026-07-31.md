# 🚦 モード別の読み方（AI共通）

> [!important] 使い方
> - 合図は前後の空白を除いて**完全一致**で判定し、その相談が終わるまでそのモードを継続する。
> - 該当モードの節**だけ**読む。ほかのモードの節は読まない。
> - **AIによって違う箇所には「Claudeの場合／Codexの場合」と明記してある。** 自分に当たる方に従う。
> - 行き先が分からない話題は [[🗂 話題別インデックス（AI共通）]] を引く。

## ① 戦略モード（`ynp97`）

読むものと進め方は `CLAUDE.md` / `AGENTS.md` の「戦略モードで必ず読む」節が正本。読んだら一言「ブリーフィングを読みました」と添える。会話の終わりに**書き戻しプロトコル**を実行する。

## ② 軽量モード（合図がないとき全部）

人生・信仰・創作・事業の相談でも、合図がなければこちら。**起動時の4ファイルは読まない。** 手早く対応し、トークンを使わない。相談ログへの追記もしない。

- **記録トリガー（例外）**: 「**記録して**」「ログして」等と言われたら、要点を [[🗒 相談ログ（追記式）]] に追記する。重要な決定・気づきに発展したと判断したら、**「これは記録しておきますか？」と一言だけ**確認してよい（勝手に長文を書かない）。

## ③ アプリ制作モード（`app97`）

戦略の4ファイルは**読まない**。コード作業に直行するためのモード。読んだら一言「アプリ台帳を読みました」と添える。

**読む順（2026-07-31改定）**

1. **対象アプリが決まっている** → `アプリ引き継ぎ/` のその**単体ファイル1本だけ**を読む。[[🧩 アプリ開発状況（AI共通）]] は開かない。
   - `シランガナ` / `Shirangana` / `しらんがな` → **正本は [[🧩 シランガナ引き継ぎ（AI共通）]]**（`アプリ引き継ぎ/C シランガナ.md` は補助）
2. **対象が未定・横断相談** → [[🧩 アプリ開発状況（AI共通）]] の**索引表だけ**を読む（約5,200文字）。そこから該当する単体ファイルへ進む。
3. 実体コード・開発記録は、必要になった分だけ読む。
4. 仕様の確認が要るときだけ [[🔭 検討中プロジェクト（オープンな問い）]] の**該当節のみ**。全文は読まない。

**進め方**: 構想を広げるより、**動くコード・直ったバグ・出せるビルド**を残すことに収束させる。「できました」と言うときは原則5の2行（`やったこと` ＋ `確かめ方（あなたの手で）`）を必ず添える。

**終了時**: 触ったアプリの**単体ファイルを更新する**。[[🧩 アプリ開発状況（AI共通）]] は索引なので、**行が増減したときだけ**直す。**詳細を索引へ書き戻さない。** 大きな方針変更があったときだけ相談ログにも1行残す。

> [!important] `ai97` との境界（2026-07-31確定）
> - **DSに実装させる話**（作業票を書く／成果物を検品する／バグを直す）＝ **`app97`**
> - **DSの設定・費用・モデル選定・環境構築・AI間の役割分担** ＝ **`ai97`**
> - 迷ったら、**成果物がコードなら `app97`**。

> [!warning] 引き継ぎファイルに必ず残すもの
> **★踏んではいけない地雷** ── 一度踏んだ失敗と、その理由。消さない。
> 実例＝0バイトのファイルを「Saved」と表示していた（screen-recorder）／日付形式を確認せず `##` 見出しを捨てて162行が消えた（日記アプリ）／設計図に日本語で書いたフォルダ名を、DSが自分のfixtureに合わせて英語で実装した（同）。
> **理由が書いてあるコードや記述を「読みにくいから」で削らない。**

## ④ 説教モード（`set97`）

戦略・アプリ系のファイルは**読まない**。釈義→説教の流れと本人の文体だけをそろえる。読んだら一言「釈義・説教スキルを起動しました」と添える。

1. **[[📖 釈義スキル（AI共通）]] と [[📖 説教スキル（AI共通）]] を対で起動する。** 流れは「釈義（本文の確定）→説教（メッセージ化）」。
   - **Claude / Cowork の場合**: exegesis スキルが自動起動する。
   - **Codex など、スキルを持たないAIの場合**: 自動起動しないので、**必ずこの2ファイルを読んで**その指針に従う。`📖 釈義スキル（AI共通）.md` は exegesis スキルの正本コピー。
2. [[📌 事実と前提（AI参照用）]] のうち、**文体・振る舞いの注意のみ**参照（本人の詩的表現を引用しない等）。事業・人物の事実部分は読み込まない。

**要点**: 本文に根のない主張（読み込み）は指摘する／忖度せず、懸念は結論を出す前に必ず述べる（最終判断は本人）／「節ごとに」と言われたら一節ずつ仕上げ、**指示があるまでファイルは書き換えない。**

## ⑤ 早天メッセージモード（`st97`）

戦略・アプリ・音楽制作系ファイルは**読まない**。最初に [[🌅 早天メッセージスキル（AI共通）]] だけを読み、内蔵された釈義品質ゲートをすべて通す。読んだら一言「早天メッセージスキルを起動しました」と添える。

- 本文批評・原語・歴史・解釈に**難所がある場合だけ** [[📖 釈義スキル（AI共通）]] の該当箇所を参照する。複数の難所や重大な神学判断があるときは全文を読む。
- `0722` のような4桁は当年の月日として `.agents/skills/st97/references/YYYY-MM.md` から箇所を引く。
- 固定パイプラインで、本文整理 → 印刷用HTML → 同内容PDF → 自動検査 → 全ページcontact sheet を生成する。**contact sheetで全ページを一度確認し、異常が疑われるページだけ原寸で見る。** PDFはプレビューで開く。
- **主成果物はHTML。** Wordは明示されたときだけ作り、その場合は [[📄 Word出力仕様（AI共通）]] と [[🌅 早天Word出力仕様（AI共通）]] を読む。
- **通常のst97一件では、続行確認を挟まない。** HTML・PDF生成を含むという理由だけで高負荷扱いしない。
- **指示があるまで説教ファイルは書き換えない。**

**二段階で進める。** 第一段階＝全体の流れと結論 → 段落分け → 各段落の簡単なまとめ → 各節の本文 → 直下の背景・語句 → 少し詳しい段落ポイント → 詳しい全体のまとめ → 五段階の適用 → 同内容の印刷用HTML生成 → PDF全ページ確認・プレビュー表示。第二段階＝指示を受けて「見ながら10分で口頭説教するための箇条書き原稿」へ収束させる。`st97` だけが入力された場合は聖書箇所または訳文を待つ。詳細条件は共通スキルを正本とする。

## ⑥ 音楽制作環境モード（`q97`）

Cubase、Logic、DAW、MIDI、オーディオ、プラグイン、音楽制作に関するMac/PC操作・周辺機器接続を扱う。戦略・アプリ・説教系ファイルは**読まない**。

[[🎛 音楽制作環境引き継ぎ（AI共通）]] を読み、索引から該当する個別記録だけを参照する。操作中は**推測で設定値を断定せず**、スクリーンショットや実機表示を優先する。終了時は、再利用できる確定設定・解決手順・つまずき・未解決を同ファイルへ更新する。

## ⑦ AI関連モード（`ai97`）

Claude、Codex、DeepSeek、Gemini、ローカルAI、外部API、OpenClaw、Obsidian連携、AI間の役割分担・記憶・費用・安全性まで、AI関連全体を扱う。戦略の4ファイルは**読まない**。読んだら「AI関連モードを起動しました」と添える。

`.agents/skills/ai97/SKILL.md` に従い、最初に [[🤖 AI関連引き継ぎ（AI共通）]] **だけ**を読む。そこから相談に関係する正本の該当節だけ参照する。過去経緯が必要な場合だけ相談ログを固有名詞で検索する。終了時は、変更内容に応じて [[🗂 話題別インデックス（AI共通）]] ／ [[🤖 Obsidian×ローカルAI引き継ぎ（AI共通）]] ／ [[🔌 外部AI連携（起動プロンプトと記憶プロトコル）]] の**該当正本だけ**を更新する。

**ローカルAIの位置づけ**: 継続して育てる本線の一つだが、目的はローカル化そのものではなく、**費用を気にせずAIを実用に使うこと**。ローカルと外部APIを分断せず、目的に応じて役割分担する。

## ⑧ 動画編集モード（`fcp97`）

Final Cut Proを中心に、早天・賛美の動画編集、Silenci、Motion、タイトル、書き出し、公開前確認を扱う。戦略・アプリ・説教・音楽制作・AI関連の台帳は**読まない**。読んだら「動画編集モードを起動しました」と添える。

最初に [[🎬 動画編集引き継ぎ（AI共通）]] だけを読み、現在地・固定ワークフロー・未解決を確認する。キー操作や症状別の対処が必要なときだけ [[🎬 FCP早見メモ]] の該当節を見る。操作中は画面状態を**推測で断定せず**、スクリーンショットや実機表示を優先し、**一度に一操作ずつ**進める。終了時は、実機で成功した操作・失敗した手順・確定設定・次回の一手を動画編集引き継ぎへ、細かい操作知識はFCP早見メモへ反映する。

## 全モード共通

### 聖書箇所を扱うとき

聖書箇所の釈義・説教準備を頼まれたら、[[📖 釈義スキル（AI共通）]] と [[📖 説教スキル（AI共通）]] を**対で起動**する（戦略／軽量モードに関わらず適用）。ただし `st97` は早天共通スキル内の同等の品質ゲートを使う軽量経路とし、難所がある場合だけ詳しい釈義手順へ戻る。

### 「記憶して」コマンド

ユーザーが「**記憶して**」と言ったら、[[🔌 外部AI連携（起動プロンプトと記憶プロトコル）]] の『記憶ブロック』形式（背景／話したこと／結論／次の一手／更新ファイル／未解決）で出力し、[[🗒 相談ログ（追記式）]] の先頭に追記する。この形式は、冷えた状態の別AI（Gemini / LM Studio等）へそのまま渡して続きを始められる引き継ぎパケットを兼ねる。

### 過去の方針を思い出すとき

ユーザーが「前に」「確か」「どうするんだっけ」「続き」など、過去の方針・設定・作業を想起する言い方をした場合は、**新しい方法を提案・作成する前に**、専用引き継ぎと相談ログを固有名詞の組み合わせで検索し、現在の実体・設定を確認する。検索結果が省略された場合は未確認扱い。**既存方針／現在の実装／代替案を区別する。**
