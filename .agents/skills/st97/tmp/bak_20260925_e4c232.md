# 📖 構造分解スキル（AI共通）

> [!important] 使い方
> - **Claude / Cowork / Codex**: 釈義・説教準備の途中で解釈上の問いを受けたら、このファイルの手順に従って応答する。
> - **ChatGPT / LM Studio（下位モデル含む）**: 下記本文をそのまま指示に貼り付けて使う。手順0〜8を順番どおり実行させるだけで再現できる。

---

## このスキルは何をするか・いつ使うか

**目的**: 問いに「要約」で答えず、「論証」で答える。本文が言っていることと言っていないことを峻別し、連結の一段一段を見えるようにする。

**起動条件**（いずれか）:
- 「なぜAがBにつながるのか」「この節はどういう論理か」という解釈上の問いを受けたとき
- 因果・条件・理由の連結で誤読が起こりやすい箇所を精査するとき
- ユーザーの疑問・反論を受けて、本文で再検証するとき（→ 禁止事項6）

**このスキルが使わないもの**: 神学者の見解の羅列、感想、一般論。使うのは本文の文法・語彙・文脈だけ。外部知識を使う場合は必ず「B・根拠」として明示する。

## 機能2：代表的な疑問の自動生成（2026-07-22追加）

ユーザーが問う前に、誤読が起こりやすい連結を検出して「代表的な疑問」として提示する機能。set97の釈義レポートには必須で付属させる（配置は釈義スキル側の規定に従う）。

### 検出パターン（7類型・この表を機械的に走査する）

対象箇所の各節を、次の7パターンで順に点検する。該当したら疑問を1つ生成する。

| # | パターン | 検出の目印 | 生成する疑問の型 |
|---|---|---|---|
| 1 | 連結の曖昧さ | 分詞構文・接続詞（〜を見て／それで／〜のゆえに、γάρ・ὅτι・ἵνα・כִּי） | XはYの原因か、それとも契機にすぎないか |
| 2 | 行為者の不明示 | 受動態（特に神的受動態）・無主語文 | 誰がこれを成立させたのか |
| 3 | 代名詞・所有格の範囲 | 「彼らの」「あなたがたの」等の指示範囲が複数読める | 誰が含まれ、誰が含まれないのか |
| 4 | 求めと応答の不一致 | 登場人物の求めと、神・イエスの応答がずれる | なぜ求めたものと違うものが与えられたのか |
| 5 | 意外な順序 | 期待される順序の逆転・先行（赦しが癒やしより先等） | なぜこの順序なのか |
| 6 | 本文の沈黙 | 読者が当然補いたくなるのに本文が言っていないこと | 本文は本当にそれを言っているか（D候補） |
| 7 | 無説明の重い語 | 信仰・義・赦し・栄光等の神学的重要語が定義なしで登場 | この語はここで何を指しているか |

### 提示形式（1問い＝3行・固定）

```
疑問n（パターン#・節番号）: （問いを一文で）
　誤読の典型: （この箇所で実際に流通している誤読を一文で）
　罠の位置: （文法・語彙のどこが誤読を許すのかを一文で）
```

### 規則

1. 提示は**3〜5個**。7類型すべてを埋めようとしない。その箇所で実害のある誤読が生じるものだけ選ぶ。
2. **この段階ではフル分解しない。** 手順0〜8のフル分解は、ユーザーが選んだ問いに対してだけ行う（トークン節約と精度のため）。
3. 各疑問には必ずパターン番号と節番号を付ける。付けられない疑問は思いつきなので捨てる。
4. 「誤読の典型」は捏造しない。実際に説教・注解で見られる読み方に限る。思い当たらなければ「読者が補いがちな読み」として明示する。
5. 提示の末尾に一行添える:「フル分解が必要な疑問の番号を指定してください」。

### 見本（マルコ2:1-12なら）

```
疑問1（パターン1・5節）: 彼らの信仰（行動）は、なぜ罪の赦しにつながったのか
　誤読の典型: 熱心な行動が赦しを勝ち取った（信仰＝功績説）
　罠の位置: ἰδών（見て）は宣告のきっかけを示すだけで、赦しの原因を特定しない
疑問2（パターン3・5節）: 「彼らの信仰」に中風の本人は含まれるのか
　誤読の典型: 他人の信仰が本人抜きで赦しを成立させた（代理信仰説）
　罠の位置: αὐτῶν（彼らの）の指示範囲を文法は特定しない
疑問3（パターン5・5節）: なぜ癒やしでなく赦しが先なのか
　誤読の典型: 病は罪のせいだから、まず罪を処理した（病罪因果説）
　罠の位置: 本文は因果を語らない（沈黙）。順序は優先順位の宣言と読むべき箇所
```

## 証拠ラベル（すべての主張に必須）

すべての主張の末尾に、次の5つのうち1つを必ず付ける。**ラベルのない主張は書いてはならない。**

**定義の正本は [[📖 説教スキル（AI共通）]] §2。** 下の表は、このファイルを単体でLM Studio等へ貼り付けても動くようにした複製なので、食い違ったら説教スキルを優先する（2026-09-05。あわせて「4つ」→5つを訂正）。

| ラベル | 意味 | 規則 |
|---|---|---|
| **A** | 本文が言っていること | 文法・語彙で機械的に確認できることだけ。 |
| **B** | 本文・文脈から妥当に導けること | 推論。**根拠を括弧内に必ず添える**（例: B・10節の論理から）。 |
| **C** | 説明上の補い | 本文の外から言葉を足して説き広げた部分（生理学・歴史・神学用語での定式化など）。「本文がそう言っている」とは言わない。**「敷衍」の語は使わない**（2026-07-25・ユーザー指示）。 |
| **D** | 本文が言っていないこと | 誤読の排除に使う。「本文はそれを言わない」と明記する。 |
| **U** | 未決・諸説あり確定できないこと | 両論併記。片方を断定しない。 |

> [!note] ラベル改定（2026-07-25・ユーザー指示）
> 以前このファイルでは **C＝諸説あり確定できないこと** としていたが、`📖 説教スキル（AI共通）` の **C＝説教的想像・説明上の補い** と衝突していた。同じ記号が別物を指す状態を解消するため、**未決・両論併記は `U` へ改名し、`C` は説明上の補い専用**とした。両スキルでラベルの意味は共通である。改定前に作成した釈義ファイル内の `C` は旧定義（未決）の可能性があるため、読み返す際は文脈で判断する（遡及修正は指示があった場合のみ）。

## 手順（この順で機械的に進める）

### 手順0：問いの確定
「この問いは、**何と何の連結**（または何の主張）を問うているか」を一文で書く。ここが曖昧なまま先へ進まない。

### 手順1：文法の切り分け
対象文の構文（分詞・主動詞・態・時制・接続詞）を確認し、次の2つを分ける。
- 文法が**直接結んでいる**もの（A）
- 文法が**特定していない**もの → 「文法はそこまで特定しない」と明記する。埋めない。

### 手順2：主語・主体の確認
各動詞の行為者は誰か。受動態は誰による行為か（神的受動態など）（A）。ここで「誰が何を成立させたか」の主語を確定する。

### 手順3：キーワードの中身の確認
問いの中心語（例:「信仰」「義」「恐れ」）が、**この本文の中で**どう描かれているかを確認する。心情か行動か、何を指しているか。本文が描いている範囲はA、明示されない中身の推定はBまたはU（確定できないとき）。

### 手順4：文脈が自ら示す論理
前後の節・段落が示す論理関係（説明・展開・対比・応答）を確認する。同じ段落が自ら答えを示していることが多い（例: マルコ2:5の問いに2:10が答える）。

### 手順5：書全体からの補強
著者の構成・並行箇所・書全体の主題からの補強があれば加える。必ず（B・根拠）と明示する。ここはA扱いにしない。

### 手順6：連鎖の一本化
分解の結果を、**番号付きの一本の連鎖（1→n）**にまとめる。各段は一歩だけ。段と段の間に飛躍を見つけたら、分解に戻って埋める（埋まらなければUとして残す）。

### 手順7：誤読の明示的排除
この箇所で起こりやすい誤読を列挙し、**どの分解番号がそれを排除するか**を示す。書式: 「①〜説（分解n・mが排除）」。排除できない読みは誤読と呼ばず、Uとして残す。

### 手順8：一言で言えば
結論を一〜二文で言い切る。新しい主張をここで足さない（足したくなったら分解に戻る）。

## 禁止事項（安全柵）

1. **ラベルなしの主張を書かない。**
2. **文法が特定しないことを断定しない。**「文法はそこまで特定しない」と書くこと自体が成果である。
3. **情報の穴を創作で埋めない。** わからないことは「本文は特定しない」「確認できない」と書く。
4. **一つの分解に複数の主張を入れない。** 一分解＝一歩。
5. **結論から逆算して本文を曲げない。** 先に分解、最後に結論。
6. **ユーザーの疑問に反射的に同意しない。** まず手順0〜5で再検証し、過程を示す。ユーザーが正しければ認め、根拠があれば議論する。基準は常に本文。
7. **聖句を記憶から引用しない。** Vault内蔵 `聖書（新改訳2017）` の該当巻ファイルから引く（釈義スキルの引用規則と同一）。

### 追記（2026-07-26・ユーザー指示）: 規律はチャットの議論にも適用する

このスキルの規律は、釈義レポートを書くときだけのものではない。**チャット上の議論・比較・言語化の応答すべてに適用する。** レポートでは守り、散文では省く、という使い分けが実際の失敗を生んだ（マルコ1:40-45と2:1-12の比較で、①片方にだけある要素〔沈黙命令〕の見落とし、②対比を閉じるための本文にない断定〔「公認経路を無視した」＝D〕、③「証し」の語の一致だけで対象の違うもの〔男の身分の認定とイエスの正体の開示〕を接続、を連続して犯した）。対策として:

1. **比較では「片方にだけあるもの」を明示的に走査する。** 存在する要素の照合だけでは不在は網にかからない。
2. **散文でも、物語的な断定にはラベルを付ける。** ラベルを付けられない文は書かない。ラベルは読者向けの表記である前に、書く側の検出装置である。
3. **同じ語で二つの文脈を接続する前に、対象（誰の・何についての）の一致を確認する。** 語の一致は概念の一致ではない。
4. **ユーザーに承認された直後こそ検証を強める。** 構造が褒められた直後は増築が加速し、構造が必要とする事実を無検証で供給しやすい。エレガントに閉じるために必要な事実ほど疑う。

## 見本（マルコ2:5「彼らの信仰を見て…あなたの罪は赦された」）

問い:「彼らの信仰（行動）は、なぜ罪の赦しにつながったのか」

**前提の確定**
- 分解1: 原文は分詞（ἰδών「見て」）＋主動詞（λέγει「言われた」）。本文が直接結んでいるのは「信仰を見た→宣告した」であって「信仰→赦しの成立」ではない（A）。信仰が赦しの原因か、宣告のきっかけかは、文法はそこまで特定しない。
- 分解2: 「赦された（ἀφίενται）」は神的受動態。赦しの主語は神であり、根拠は彼らの側にない（A）。この時点で「行動が赦しを生み出した」読みは文法的に閉じる。

**「彼らの信仰」の中身の分解**
- 分解3: イエスが「見た」のは心の中の信念ではなく、担ぐ・帰らない・屋根をはがす・吊り降ろすという一連の行動（A）。
- 分解4: その信仰の内容は「イエスなら癒やせる」という治癒への期待（B・文脈から）。彼らは赦しを求めていない。信仰の内容の正確さが条件だったのではない。
- 分解5: 「彼らの」に本人も含めて読むのが自然（B・搬送への同意なしはありえない）。ただし宣告は「子よ、あなたの罪は」と本人個人に向く（A）。

**連結の論理**
- 分解6: 信仰は「支払い」ではなく「受け取る手」。代価は10:45で宣告者自身が払う（B・マルコの構成から）。屋根の労力が償ったのなら「大きな罪には大きな屋根」が要ることになり、福音の構造が崩れる。
- 分解7: 連結の核心は、信仰の強さや内容ではなく**宛先**。赦しは神の専権（7節）→その権威を人の子が持つ（10節）→ゆえにイエスへ向かった信仰は、本人たちも知らないまま、赦す権威を持つ方に届いていた（B・10節が自ら示す論理）。
- 分解8: イエスは「病は罪のせい」という因果を語っていない（D・ヨハネ9:3参照）。語ったのは優先順位——最深の必要は歩行ではなく赦し。

**連鎖**: 1. 癒やしを期待して届くまで行動した → 2. イエスがそれを信仰と承認した → 3. その信仰は意図を超えて、赦す権威を持つ方への信頼として機能した → 4. イエスは求め（癒やし）ではなく神が与えるもの(赦し)から与えた → 5. 根拠は神の恵み（受動態）と後に払われる代価（10:45）。信仰は接触点。

**排除される誤読**: ①信仰＝功績説（分解2・6）②代理信仰説（分解5）③熱心への報酬説（分解4・7）④病罪因果説（分解8）

**一言で言えば**: 彼らの行動は罪を赦す力を持っていなかった。しかしその行動は、罪を赦す力を持つ方の前に彼を運んだ。赦しの原因はイエスにあり、信仰は宛先を正しく指しただけである。

## 釈義レポートとの関係

- チャットで行った分解は、set97正式出力様式の**「補」として圧縮せず全文のまま**該当節に収める（釈義スキル「論証の保存」規定と同一）。短い箇条書きへの要約は様式違反。
- **指示があるまでファイルは書き換えない**（説教モード共通原則）。

## 出力前の形式検査（見れば真偽が判る3点だけ）

出力を目で走査して確認する。**内容の当否ではなく、書式が揃っているかだけを見る。**

1. ラベル（A/B/C/D/U）の付いていない主張が残っていないか
2. 根拠の括弧が付いていないBが残っていないか
3. 排除した誤読に、対応する分解番号が付いているか

（2026-09-05：旧5項目のうち「連鎖に飛躍がないか」は手順6、「聖句を記憶から引用していないか」は禁止事項7が本体なので削除した。残した3点は、出力を見れば真偽が判定できるので検査として成立する。）
