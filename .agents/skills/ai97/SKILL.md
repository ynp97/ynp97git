# AI関連モード

## 起動

1. 戦略・アプリ・説教・早天・音楽制作の台帳を最初から読まない。
2. `🤖 AI関連引き継ぎ（AI共通）.md` だけを最初に読み、相談内容に対応する正本へ進む。
3. 各正本は全文でなく、索引・見出しから関係する節だけ読む。
4. `ai97`だけが入力された場合は「AI関連モードを起動しました」と伝えて相談内容を待つ。

## 読み分け

- AIの役割分担、どのAIに何を任せるか: `🗂 話題別インデックス（AI共通）.md` の該当節
- LM Studio、ローカルモデル、外部API、OpenClaw、Copilot、Vault QA、RAG、画像・音声AI: `🤖 Obsidian×ローカルAI引き継ぎ（AI共通）.md` の該当節
- AI間の記憶、起動プロンプト、引き継ぎ: `🔌 外部AI連携（起動プロンプトと記憶プロトコル）.md` の該当節
- 特定アプリの実装: AIの役割を決めた後、`app97`または対象アプリの単体引き継ぎへ渡す
- 聖書・説教・早天、文書・制作物: AI選定だけ扱い、本文作業は各専用モードへ渡す
- 最新モデル、価格、仕様: 公式情報で最新確認し、確認日を残す
- 「前に」「続き」「どうするんだっけ」: 上記正本を固有名詞で検索し、不足時だけ相談ログの関連箇所を検索する。ログ全体は読まない。

## 進め方

- 目的を先に確認し、特定モデルやローカル／クラウドを守ること自体を目的化しない。
- 設定・導入・復旧へ入る前に、症状を直すより問題自体を消せる上位経路を先に確認する。最低限、①同じAI／アプリを対象端末へ直接入れる、②画面共有・コネクタ・API・既存ログインでAIが直接扱う、③公式ネイティブアプリ／自動セットアップ／移行機能を使う、④端末や役割分担を替える、を比較する。別端末へのコマンド転記やユーザー中継を一度でも求める前にこの確認を済ませ、二度目の転記依頼は禁止する。製品の導入・復旧は、記録済みの旧手順より現在の公式導入経路を先に確認する。
- 確認済みの現行構成、検討中の代替案、未検証の候補を分ける。
- モデルの能力と、現在のアプリ・APIから実際に使える機能を分ける。
- 費用、品質、画像・音声対応、プライバシー、Mac負荷、実装手間で役割分担する。
- 記録済み手順を実画面・設定値・実行結果で再確認する。
- 現実の設定・認証・画面操作は、難易度や「雑務」という印象で扱わず、`現在の状態を観測 → 一操作 → 実際の反応を確認 → 状態を更新` の制御ループとして扱う。期待した反応を確認するまで次の操作へ進まない。
- 期待した状態へ移らなかった場合は、説明や同じ操作の反復を始めず、最後に確認できた成功状態と最初の失敗状態を特定する。その区間だけを修復するか、その区間を通らない別経路へ切り替える。
- 視界拡張を物理的な画面・ログ・ミラーリングだけに狭めない。行き詰まり時は、現在の問題設定を仮説へ戻し、別の抽象度・別分野の類推・別の因果モデルから同じ事実を捉え直す。「不足している情報」だけでなく「自分がすでに知っているのに、現在の枠組みのため使っていない知識・機能・解法は何か」を明示的に検索する。
- ユーザーが提示した直近の具体例に新しく固定されない。その例が有効なら上位原理を抽出し、まだ提示されていない可能性まで探索する。複数端末・アプリの観測統合、ミラーリング、連携機能、ログ、通知、既存ツールは候補の一部であり、視界拡張そのものではない。
- 賛同や原則の説明を完了扱いにしない。ユーザーが「やって」と求めている場合は、その原則を直後の操作と検証に適用し、現実の成功状態まで確認する。
- 同じ経路が二度外れたら、正本復旧・別経路・変更範囲縮小を比較する。

## 終了時

- 変更内容に応じて、AI実行環境引き継ぎ／DS運用引き継ぎ／外部AI連携の該当正本だけを更新する（AI司令塔は2026-07-31に廃止。行き先は 🗂 話題別インデックス）。
- 再利用できる手順には「最終確認: YYYY-MM-DD」を残す。失敗した手順は修正するか「要精査」とする。
- 大きな方針変更だけ `🗒 相談ログ（追記式）.md` に短く記録する。
