# Accordance聖書モジュール → Vault内蔵聖書（手順・形式・変換表）

最終確認: 2026-09-28（`verify_bibles.py` 全項目OK）
作ったもの: `聖書（ESV）` `聖書（ギリシャ語NA28）` `聖書（ヘブル語HMT）`（新改訳2017は2026-07に `scripts/sky_generate_bible.py` で作成済み）

## 0. 使い方（ふだんはこれだけ）

- 節を引く: `python3 scripts/verse.py マルコ4:26-34 [sky] [esv] [gk] [he]`（版を省くと新改訳・ESV・原語をまとめて出す。巻ファイルを丸ごと読まない＝トークン節約）
- 生成・差し替えの後の確認: `python3 scripts/accordance_extract/verify_bibles.py`（節数・重複アンカー・既知の節の本文・χ/ξ取り違え・LORD復元を機械的に見る。NGなら終了コード1）

## 1. 出力の形式

- 1巻1ファイル。各節 `番号　本文 ^章-節`（全角空白、行末ブロックアンカー）。新改訳2017と同じなので `parallel_texts.py` 系の正規表現がそのまま使える。
- ファイル名: `ESV 創世記.md` / `NA28 マタイの福音書.md` / `HMT 創世記.md`（新改訳とリンク名がぶつからないよう接頭辞つき）。
- 版ごとの約束:
  - ESV: 詩篇の表題は `0`（^章-0）。ESVが脚注に外した節は欠番。二重角括弧は ⟦ ⟧。LORD/GOD はStrong番号 H3068/H3069/H3050 から復元（God は H3069、または H3068 で直前に Lord がある場合だけ GOD）。出3:14 の I AM WHO I AM / I AM は個別に大文字化。
  - NA28: 各書冒頭の書名（inscriptio）は `0`。節番号はNA28（2コリ13章は13節まで、黙12:18あり）。本文批評記号は元データに無い。
  - HMT: **章節はヘブル語聖書の番号**。ケティーブ [ケレー]。׀＝パセク、末尾の פ／ס＝段落記号。

## 2. モジュールの取り出し（ここで詰まりやすい）

- 場所: `~/Library/Application Support/Accordance/Modules/Texts/〇〇.atext`（パッケージ＝フォルダ。中の同名ファイルが本体）。
- **ライブラリフォルダはCoworkの接続フォルダとして許可されない。** Finderで `Vault/tmp/` にコピーする（AIが操作する場合: Finderの「移動 > フォルダへ移動…」。ダイアログはバックグラウンド操作できないので全画面操作の許可が要る）。
- 手持ちモジュール（2026-09-28時点）: ESVS, GNT28-T, HMT-W4, SKY2017, LXX1, LXX-B, LXX2, KJVS, NRSVS, NET, NKRV, SHINKAI, SHINKYO, WEB ほか。**LXX1（七十人訳）も同じ方法で内蔵できるはず**（ギリシャ語なので Helena 変換表が流用できる見込み。未検証）。

## 3. モジュールの内部構造（共通）

- エンディアンはモジュールごとに違う: **ESVS・HMT-W4・SKY2017＝ビッグエンディアン、GNT28-T＝リトルエンディアン**。
- 章構造（`acc.py` の `Mod`）: 「書ごとの累積章数 u16×書数」→「書の開始節 u16×書数（上位ビット立ち）」→「(0, 総章数) または (総章数, 0)」→「各章の開始節 u16（&0x7fff、1始まり）」。累積章数の表は最初の2巻の章数（例 50,90）で検索して見つける。
- 節の枠（スロット）はAccordance独自: 詩篇の表題・書名（inscriptio）も1枠、本文の無い節は枠が無い。枠→節番号は、枠数が標準（`std_versification.json`）と同じならそのまま連番、少なければ書ごとの対応表（u16の増加列 1,2,3…、値＝標準の書内通し番号）で決める（`labels_generic`）。
- 語彙表: 「語数 u32」→「オフセット u32×(語数+1)」→「文字列の連結」。**語 i ＝ blob[o[i]-1 : o[i+1]-1]**（1ずれの約束）。
- 本文: 語番号（1始まり）の列＋節ごとの開始位置表。句読点は特別な番号で、句読点文字列の表が語彙表の手前にある（同じ1ずれの約束）。

## 4. モジュール別メモ（オフセットは各 gen_*.py にもある）

### ESVS（The Holy Bible, ESV with Key Numbers, Version 6.5）
- 語彙 14,823語（MacRoman）。本文は u16、967,023トークン、開始 606582。節表 336702（31,202）。
- 句読点コード 0x7ef5〜（表の順）。0x7ffe＝無視してよい印、0x7fff＝次の語が2回続く（1回だけ出す）、`@`＝段落、`#`＝脚注位置、タブ＝詩の行。
- トークンごとのStrong番号（u16）が本文の後ろにあり、キー表（G0001…H8674）で番号化。**tag v → keys[v-1]**。8504＝H3068、8505＝H3069、8486＝H3050。
- 検証用: 別形式の表示用本文（相互参照の記号入り）が 10735269 から、節オフセット表 10610456。これと全節照合した。

### GNT28-T（NA28, Mounce tagging, Version 3.7）
- 語彙 19,034語（Helena）。本文 u32 LE、166,678トークン、開始 447159。節表 381851（7,968）。
- 句読点: -101〜-119（u32の負値）。-104 . / -105 , / -106 · / -107 ; / -109 [ / -110 ] / -112 — / -113 · / -114 ⟦ / -115 ⟧ / -117 , / -118 ( / -119 )。-1＝次の語が2回続く。
- **変換の要点: c＝χ、x＝ξ。** 一度逆にして全28巻を作り直した（2026-09-28）。記号の対応は `helena_greek_map.tsv`（62パターン）。記号の並び順は 気息→分音→アクセント→下書きイオタ にしてからNFC。

### HMT-W4（Leningrad Codex, Westminster 4.22, Version 3.4）
- 書の順はヘブル語聖書の順（…マラキ, 歴代誌上下, 詩, ヨブ, 箴, ルツ, 雅, 伝, 哀, エス, ダニ, エズ, ネヘ）。
- 語彙（形態素）36,359、トークン列は形態素単位（接頭辞・接尾辞が別トークン）で、マケフもソフパスークも無い。**使ったのは表示用本文**: 節末オフセット u32 BE×23,214 が 13138394、本文が 13231250 から。
- 表示用本文の記号: `_`＝マケフ、`:`＝ソフパスーク、` p`/` s`＝ペトゥハー/セトゥマー、0xD1＝パセク、`]ケレー[`（左右逆）、`)Ê(`＝ケティーブの無いケレー、0xCA＝幅調整（無視）、`¿`の直後が w＝そのワウのホーレム。
- 変換: 字母は `yehudit_hebrew_map_single.tsv` 冒頭、記号は字母ごとのバイト列単位の表 `yehudit_hebrew_map_clusters.tsv`（2,275通り）→無ければ1バイト表。後処理: レビア＋ゲレシュ・ムクダムの順を入れ替え、パシュタが2つある語は1つ目をカドマに（WLCの慣例）。

## 5. 変換表の作り方（別モジュールでやり直すとき）

- 表はAIの推測ではなく、**公開テキストと語を突き合わせて多数決で学習**した。公開テキストは学習にしか使わず、本文はモジュールのもの。
  - ギリシャ語: SBLGNT（`https://raw.githubusercontent.com/LogosBible/SBLGNT/master/data/sblgnt/text/{Matt..Rev}.txt`）→ `learn_gr.py`
  - ヘブル語: OSHB（`https://raw.githubusercontent.com/openscriptures/morphhb/master/wlc/{Gen..Mal}.xml`）→ `learn_heb2.py` で語の組を作り、`heb_conv.py` の `learn()`
- 結果の一致率: NA28とSBLGNTの語一致 98.3%（残りは本文の異読）、HMTとOSHBの語一致 99.5%（残りはケティーブの母音付け等）。

## 6. 落とし穴（実際に起きたこと）

1. 変換表を直したあと**出力を作り直さずに**報告しかけた（χ/ξ）。→ 直したら必ず再生成し、**出力ファイルそのもの**を `verify_bibles.py` で確かめる。
2. 接続フォルダでは rm も tar の上書きもできない。→ 差し替えは Python で `open(path,'w')` して中身を書く。
3. オフセットの「1ずれ」を間違えると語の頭と尻が1文字ずつずれる（'uphZ' のような語が出たらこれ）。
4. ESVの本文には LORD と Lord の区別が無い（Strong番号が必要）。
5. ヘブル語の章節は英語と違う。英語の番号で探して「本文なし」になったら、まずこれを疑う（verse.py は章の節数が違うと警告する）。
