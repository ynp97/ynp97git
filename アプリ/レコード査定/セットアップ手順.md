# レコード査定（ローカルQwen3-VL / LM Studio）セットアップ手順

写真をMac上のQwen3-VLに読ませて査定表を作ります。**写真は外に出ません。チャットのAIのトークンも使いません。**
あなたの環境：**メモリ32GB・LM Studioインストール済み**。

---

## どのモデルがいい？（32GBの“一番いい”）

- **おすすめ：Qwen3-VL 30B-A3B（4bit / MLX）** … 30Bだが実際に動くのは約3Bぶん（MoE）なので、**精度が高いのに速い**。32GBに4bit（約17–19GB）で載る。型番・日本語の読みに有利。
- 速さ最優先なら **Qwen3-VL 8B**（軽快・十分実用）。
- 32Bの“dense”版も載るが、全パラメータが動くぶん遅め。今回は 30B-A3B が一番バランス良し。

LM Studioの検索窓で「**Qwen3-VL**」と入れて、**30B（4bit/MLX）** を選んでダウンロード。重すぎたら 8B に切替。

---

## 手順（LM Studio）

1. **モデルを入れる**：LM Studio左の🔍検索で「Qwen3-VL」→ 30B（MLX 4bit）を Download。
2. **サーバーを起動**：左メニューの「**Developer / Local Server**」タブ → 上で今のモデルを選んで **Start Server**。
   - 既定のURLは `http://localhost:1234`（スクリプトはこれを見ます）。
   - 「Server」画面に出ている**モデルID**を控える（実行時に使う）。
3. **画像ライブラリ**（縮小で高速化）：ターミナルで
   ```
   pip3 install requests pillow
   ```
4. **実行**：写真は初期設定でデスクトップの「e-bay PIC」を見ます。
   ```
   cd ~/"Documents/Obsidian Vault/アプリ/レコード査定"
   python3 record_lister.py --model "ここにLM StudioのモデルID"
   ```
   ※ `--model` を省くと既定 `qwen/qwen3-vl-30b` を送ります。LM Studioが別IDを表示している場合は、その文字列を `--model` に渡してください（多くの場合ロード中モデルに自動で当たります）。
   別フォルダの写真：`--photos "/フォルダのパス"`

5. **結果**：写真フォルダの隣に **`_査定結果`** フォルダができます。
   - `査定シート_qwen.md`（Obsidianで開ける表）
   - `査定シート_qwen.csv`（Excel用）
   - `results.json`（生データ）

---

## （任意）Discogsの相場・再発も自動取得

無料トークンで版数・最安値・出品数まで表に入ります。
1. Discogs無料登録 → Settings → Developers → **Generate token** をコピー
2. 実行：
   ```
   DISCOGS_TOKEN=トークン python3 record_lister.py --model "モデルID" --discogs
   ```
   ※ 1分60回制限。枚数が多いと自動で間隔を空けます。

## Ollamaで動かしたい場合（参考）

```
ollama pull qwen3-vl:30b-a3b        # 重ければ qwen3-vl:8b
python3 record_lister.py --backend ollama --model qwen3-vl:30b-a3b
```

## つまずいたら

- 接続エラー → LM Studioの **Start Server** を押し忘れ。ポートが違うなら `--base-url http://localhost:ポート/v1/chat/completions`。
- モデルエラー → `--model` をLM Studio画面のIDに合わせる。
- 読みが甘い → 写真で**型番・レーベル名・バーコード・盤のラベル面**がはっきり写るほど精度UP。
- 重い/落ちる → 8B（または30Bの低bit）に切替。

> この読み取りは「たたき台」。相場・再発・最終的な出品判断は本人が確認する前提です。
