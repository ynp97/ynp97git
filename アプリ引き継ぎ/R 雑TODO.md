## 2026-08-17 TODO決定版 3.0 ── 期日と目処を一本化

**確認の状態**: ビルドが通り、`/Applications/ZatsuTodo.app` へ入り、起動して動くことを**本人が実機で確認**（2026-08-17）。**下の「まだ見ていないこと」は未確認のまま。**

**きっかけ**: 本人から「今日というところを押した時、今月までしかソートされて表示されない。全部ソートして、全部見れるようにして」。

**★踏んではいけない地雷（3.0の元凶）── 同じことを指定する持ち物を4つ持っていた**

2.xは時間の指定を `date（期日）` `timeframe（目処）` `placement（今日/今週/今月/プール）` `plannedDate（やる日）` の**4つ**で持っていた。4つが互いに食い合った結果、

- 画面の段は `placement` 由来の3段（今日／今週／今月）しか作られず、
- 「来月中・半年以内・今年中・いつか」の目処タグは**どの段にも対応する場所が無く**、雑プール画面にしか出なかった。

コードのコメントにも「それより長い目処は長期計画へ展開せず、雑プールに残す」と書いてあり、**バグではなく設計どおりの動作だった。** 症状は「表示されない」だが、原因は「同じことを言う持ち物が4つある」。**表示側だけ直すと、また同じところへ戻る**（実際、最初に段を2つ足す小さい直し方をしたが、本人の判断で持ち物の統一へ切り替えた）。

**3.0の決めごと（本人指示・2026-08-17）**

- 時間の指定は **期日** と **目処** の2つだけ。`placement` と `plannedDate` は廃止。
- **画面の段＝目処タグそのもの**（`timeframeTags` の並び順）。設定でタグを足せば段が増える。ここに出ないTODOは無い。
- **期日は日にち指定のあるものだけ**に付く。期日があれば**目処は日付から自動**で決まる（本人選択：自動で決まる方）。
  - 判定順は既定タグの並びに合わせてある＝今日中→今週中→今月中→来月中→半年以内→今年中→いつか。**「半年以内」が「今年中」より前にあるので、年内の日付でも半年以内に入る時期がある。** これは本人のタグ順どおりで、意図的。
- **期日があるものに目処を選び直すと、期日が外れる。** そうしないと選んだ目処が効かないため（メニューにも明記）。
- **期限切れ**（期日が過ぎたもの）は目処に関係なく最上段。0件なら枠ごと出ない（本人選択）。
- **雑プールタブ廃止**（本人選択）。目処を決めていないものは「いつか」の段へ。タブは `TODO` と `ルーティーン` の2つ。完了済み一覧と「完了済みを掃除」はTODO画面の最下部へ移した。
- ルーティーンは変更なし（毎日／毎週＋曜日指定）。「今日中」の段の上に出る。

**既存データの移行**（`TodoItem.init(from:)` の中。読み込み時に一度だけ走り、保存すると古いキーがファイルから消えるので二度目以降は素通り）

| 2.xの状態 | 3.0 |
|---|---|
| `placement` = today / week / month | 目処 = 今日中 / 今週中 / 今月中 |
| `plannedDate` が**未来** | 期日へ昇格 |
| `plannedDate` が**今日以前** | 目処 = 今日中（日付にはしない） |
| `timeframe` だけ入っていた | そのまま |

- **★「やる日が今日以前」を日付にしなかったのは判断**。日付のまま移すと、8月11日に今日へ置いたものが**一斉に期限切れへ落ちる**ため。ここは実機で見て変なら直す。
- 実行前バックアップ: `install_update.sh` が `~/Library/Application Support/ZatsuTodo/todos.before-v3.0-20260817.json` へ退避する。**バックアップ名は版ごとに手で直す**（2.5用の名前のまま固定されていて、実行すると8/11の復元点を潰すところだった）。

**内部の作り直し**: 2.xは「今週」の判定のたびに「今日」の配列を、「今月」の判定で両方を作り直していた（件数が増えるほど重くなる形）。3.0は `grouped` で1周に畳んだ。**1.2でハングを踏んでいる箇所なので、描画を重くする方向へは戻さない。**
