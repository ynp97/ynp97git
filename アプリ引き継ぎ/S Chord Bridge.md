# S. Chord Bridge

### S. Chord Bridge（Cubase⇄Logic 受け渡しMacアプリ）

- 種別: SwiftUIネイティブMacアプリ。CubaseとLogic Proの間でコード・MIDI・オーディオを往復させる受け渡しツール。
- デスクトップ版: `/Users/yoshiakinagumo/Desktop/Chord Bridge.app`
- ソース: `アプリ本体/ChordBridgeMac`
- ビルド出力: `アプリ本体/ChordBridgeMac/build/Chord Bridge.app`
- Bundle ID: `jp.ynp97.chordbridge`
- 状態: **0.9.2 / build 12**（2026-07-24にデスクトップ版へ反映済み・起動確認済み）。

想定する流れ:
1. Cubaseのコードパッドでコード進行を作る
2. コード進行をMIDI化してLogicへ渡す
3. LogicのSession Playerに演奏させる
4. Session Playerの演奏をMIDIまたはオーディオで書き出す
5. Cubaseへ戻してミックスする

実装済みの主な機能:
- Cubase側の複数コードを、順番・位置・長さを保った一つのMIDIパートへまとめる
- LogicのSession PlayerリージョンをMIDIリージョンへ変換（Accessibility API使用）
- LogicのMIDI保存画面／オーディオ書き出し画面を開く
- MIDI／WAV／AIFFを受渡カードへ読み込み、Cubaseへドラッグ
- ファイルコピーとFinder表示
- Cubaseの背面へ隠れないフローティング表示
- Dock登録、「C7・音符の橋・コード」専用アイコン

0.9.2の修正内容（0.9.1の重要不具合対応）:
- 不具合: Session Playerを「MIDIで受け取る」と、変換後にフォーカスが移動し、元のコードMIDI（例: Amin7）を書き出してしまう。誤出力例＝`~/Desktop/プロジェクト 1.mid`。
- 修正: 変換前に選択中Session Playerリージョンの画面位置を記憶し、変換後も同じ位置をクリック→右クリック→そのリージョンだけをMIDI書き出しする処理順に変更。

2026-07-24 実運用で判明した重要事項（Chord Bridgeより上流の問題）:
- Logic→Cubaseは、**Chord Bridgeの自動化に頼らずLogic標準のドラッグ書き出し**が本命という結論。手順書は [[🎹 Logicの演奏をCubaseへ運ぶ（手作業・確実版）]]。
- **根本原因を実解析で確定**: LogicのSession Player（Bass Player）を書き出したMIDIは、SMFフォーマット0・1トラックだが、**音符がMIDIチャンネル1・2・3にまたがる**（SysExは0個）。Cubaseがこれをチャンネルごとにトラックへ割り、1本のベースが3トラック（メイン＋最低音＋「SysExデータ」表示）に割れて見えていた。
- **一度きりの解決（本人が実施・確認済み）**: Cubase → 環境設定 → MIDI → MIDIファイル → 読み込みオプションで「**ファイルタイプ 0 の場合はチャンネルを分割**」をOFF、「ドロップされたファイルを1つのパートとして読み込む」をON。以後1ベース=1トラックで入る。
- 取り込み後にパートが少し長いとき＝矢印ツール＋スナップで右端を詰める／尺ごと縮めるなら「サイズ変更:タイムストレッチを伴う」モード。
- Chord Bridge本体（0.9.2）の「MIDIで受け取る」自動化の実機検証は、この上流問題を優先したため未完のまま。手作業ルートで足りるなら自動化修正の優先度は下げてよい。

注意:
- アドホック署名なので**再ビルドするたびにアクセシビリティ許可が無効化**される。スイッチがオンに見えても旧ビルドの登録の場合があり、オン・オフでは直らない。一覧から削除→追加し直しが必要。
- Logicのリージョンはファイルではないため、Chord Bridgeへ直接ドラッグできない。先にMIDIまたはオーディオとして書き出す。
