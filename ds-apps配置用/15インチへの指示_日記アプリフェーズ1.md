## 0. この作業票だけの特別ルール（最優先・AGENTS.mdより優先）

通常の `AGENTS.md` は「迷ったら作業票へ書いて**止める**」だが、**この作業票に限り、止まらずに進めること**。理由は、本作業に業務上の判断（本人しか知らない区分）が一切含まれず、技術的な選択しか残っていないため。

### 止まらないための行動規則

1. **質問して待たない。** 仕様に書いていない技術的細部（色の具体値、余白、フォントサイズ、内部の型名、ファイル分割の仕方など）は**自分で決めて実装し、決めた内容を作業票の「自分で決めたこと」へ記録する**。
2. **エラーで止まらない。** ビルドが通らない場合は、**別のやり方を最大3回試す**。それぞれ何を試して何が起きたかを記録する。3回で通らなければ、その機能だけ最小限の代替実装（例: 一覧だけ出す）に切り替えて次のタスクへ進む。**全体を止めない。**
3. **手が空いたら次へ。** タスク一覧（§4）は上から順に、終わったものから次へ。全部終わったら§7の仕上げへ。
4. **作業を投げ返さない。** 「本人の確認が必要です」で終わらせない。確認が要ると判断したものも、**いったん自分の判断で実装してから**、作業票に「要確認」として書く。
5. **例外（ここだけは本当に止まる）**: 実データ・APIキー・証明書が必要になった場合、または他人の個人情報を扱う必要が出た場合。これらは本作業に登場しないはずなので、出てきたら仕様の読み違いを疑うこと。

### 触ってはいけないもの

- **ネットワーク上の他のMac・共有ボリューム・画面共有先へアクセスしない。** この作業はこの機械の中だけで完結する。
- `ynp97/ds-apps` 以外のリポジトリを新規作成しない（常設ルールどおり）。

## 1. 何を作るか

macOS向けの**日記閲覧アプリ**（Swift / SwiftUI）。Markdownで書かれた日記ファイルを読み込み、3ペインで表示する。

**フェーズ1は「読むだけ」。ファイルへの書き込み・編集・削除は一切実装しない。** 保存機能を作らないこと。これは安全のための意図的な制約であり、後のフェーズで別途実装する。

配置先: `apps/diary-viewer/`

---

## 2. 読み込む対象のデータ形式

日記は**年ごとに1つのMarkdownファイル**にまとまっている。ファイル名は `2013.md` 〜 `2026.md`。

### ファイルの構造

````markdown
---
title: ジャーナル 2026
type: journal
year: 2026
entries: 32
---

# ジャーナル 2026

[[_ジャーナル目次|← 目次]]

## 2026-01-06（火）6:45:26

> 🌤 1°C ほぼ快晴 ｜ 📍 学研教室, 八千代市, 千葉県, 日本

ここが本文。複数行にわたる。
2行目、3行目と続くことがある。

## 2026-01-07（水）14:14:27

> 🌤 7°C 曇り ｜ 📍 自宅, 八千代市, 千葉県, 日本

本文。写真が入ることがある。

![[c80534fc8eee12ec783f9f56b83be062.png]]

写真の後にも文が続くことがある。 #買い物
````

### パーサーの仕様（ここが最重要）

- **エントリの区切りは `## ` で始まる行**。この行から次の `## ` の直前までが1エントリ。
- 見出しの形式: `## YYYY-MM-DD（曜）H:MM:SS`
  - 曜日は日本語1文字（月火水木金土日）。
  - **時刻はゼロ埋めされている場合とされていない場合の両方がある**（`6:45:26` と `14:14:27` の両方が実在する）。両方を必ず受け付けること。
- **引用行 `> 🌤 …｜📍…` は本文ではなくメタ情報**として別に持つ。天気・気温・場所。
  - **この行が無いエントリもある。** 無くてもエラーにしない。
  - 形式が想定と違っても落ちないこと（読めない部分は空にして本文表示は続ける）。
- **添付の埋め込みは `![[ファイル名]]` 形式**。拡張子は `.png` `.jpeg` `.jpg` `.mp4` `.mov` など。
  - 実体は日記ファイルとは別のフォルダにある（§3参照）。
  - 埋め込みは**本文中の位置を保つ**こと（写真の前後の文が入れ替わらないように）。
- **タグは `#タグ名` 形式**（例 `#買い物` `#EPOC`）。本文中から抽出して、エントリのタグ一覧として持つ。
  - 半角 `#` の直後に文字が続くものをタグとみなす。行頭の `# ` （半角スペース付き＝見出し）はタグではない。
- frontmatter（`---` で囲まれた部分）と、`# ジャーナル YYYY` 見出し、`[[_ジャーナル目次|← 目次]]` 行は、エントリではない。読み飛ばす。

### パーサーの検算（必ず実装してテストする）

- 読み込んだエントリ数を数え、frontmatterの `entries:` の値と一致するか検証する関数を作る。
- 不一致なら**警告を出す**（クラッシュはしない）。
- この検算をテストコードで確認すること。

## 3. フォルダ構成（読み込み先）

アプリは次の構成を前提にする。

```
<選んだフォルダ>/
  ジャーナル/
    2013.md 〜 2026.md
  media/
    ジャーナル写真/     ← 画像の実体
    ジャーナル動画/     ← 動画の実体
```

- 起動時、**フォルダを選ぶ画面**を出す（`NSOpenPanel`）。選んだパスは次回起動時に復元する（`UserDefaults`）。
- **フォルダが未選択・存在しない場合は、同梱のテスト用データ（§5）を表示する。**
- 画像・動画は `media/ジャーナル写真/` と `media/ジャーナル動画/` の両方を探し、ファイル名で解決する。

> **重要**: この機械には本物の日記データは無い。**§5のテスト用データだけで開発・確認すること。** 本物のデータは本人のMacにあり、後で本人が接続する。

## 4. 作るもの（上から順に）

### 4-1. パーサー（最優先・最も丁寧に）

上記§2の仕様どおり。`Entry` 構造体は最低限これを持つ:

```swift
struct Entry {
    let date: Date          // 日付
    let time: String        // 元の時刻文字列（表示用にそのまま保つ）
    let weekday: String     // 曜日（日本語1文字）
    let weather: String?    // 引用行から。無ければ nil
    let location: String?   // 引用行から。無ければ nil
    let body: String        // 本文（引用行と見出しを除く）
    let attachments: [String]  // ![[...]] のファイル名
    let tags: [String]      // #タグ
    let year: Int           // どの年ファイル由来か
}
```

**テストを書くこと。** 最低限、次のケースを通す:

- ゼロ埋めありの時刻（`14:14:27`）とゼロ埋めなしの時刻（`6:45:26`）の両方
- 引用行があるエントリと、無いエントリ
- 写真が本文の途中に挟まるエントリ
- 同じ日に複数エントリがあるケース
- タグが複数あるエントリ
- frontmatterの `entries:` と実件数の一致検算

### 4-2. 3ペインのUI

`NavigationSplitView` で3ペイン。

**左＝サイドバー**
- 「すべて」「今日」「この日（過去の同じ月日）」
- 年の一覧（2013〜2026）。各行に件数を出す。
- 「ゴミ箱」「設定」は**項目だけ置いて中身は未実装でよい**（フェーズ1では押しても何も起きなくてよい）。

**中央＝エントリ一覧**
- **月ごとにグループ見出し**を出す。表記は**西暦**（例「2026年7月」）。**和暦は使わない。**
- 各行に: 日付の大きな数字＋曜日（小さく）／本文の冒頭2〜3行のプレビュー／右端にサムネイル（画像があれば。無ければ何も出さない）／下に時刻と場所を小さく。
- 新しい日付が上（降順）。
- 選択行はハイライト。

**右＝詳細**
- 上部に「2026年6月17日（水）22:15」のような見出し。
- 本文を読みやすい行間で表示。
- **画像は本文中の位置にインライン表示**（クリックで拡大できるとなお良い）。
- **動画は `AVKit` の `VideoPlayer` でその場で再生できるようにする。**
- 添付ファイルが見つからない場合は、壊れた表示ではなく「（ファイルが見つかりません: ファイル名）」と出す。

**見た目**: ダーク基調で落ち着いた配色。余白は詰めすぎない。具体的な色・サイズは**自分で決めてよい**（決めた値を作業票に記録する）。

### 4-3. 検索

- 中央ペイン上部に検索欄。
- 本文・タグを対象に**部分一致**で絞り込む。
- 日本語が扱えること（`localizedStandardContains` など）。

### 4-4. タグ絞り込み

- サイドバーかツールバーに、出現したタグの一覧を出す。
- タグを選ぶと、そのタグを含むエントリだけに絞る。

### 4-5.「この日」

- 今日の月日と同じ、過去の年のエントリを集めて表示する（例: 7月30日なら、2013〜2025年の7月30日）。

## 5. テスト用データ（同梱する）

`apps/diary-viewer/Fixtures/` に、**自分で作った架空のデータ**を置く。

- `ジャーナル/2024.md`、`ジャーナル/2025.md`、`ジャーナル/2026.md` の3ファイル。各10〜20エントリ程度。
- `media/ジャーナル写真/` に、**コードで生成した単色や図形の画像**を数枚（実写真を使わない）。
- `media/ジャーナル動画/` に、**数秒の生成動画**を1本（作れなければ動画は省略し、その旨を作業票に書く）。
- 内容は**完全な架空の日常**にする。実在の人物名・住所・電話番号を書かない。
- **§2で挙げたすべてのエッジケースを、このテストデータに必ず含めること**（ゼロ埋めなし時刻、引用行なし、写真が途中に挟まる、同日複数、タグ複数）。

## 6. 制約

- **書き込み機能を作らない。** ファイルを開くのは読み取り専用で行う。保存・編集・削除のコードを1行も書かない。
- 外部ネットワーク通信をしない。API呼び出しをしない。
- 外部ライブラリは原則使わない（標準のSwiftUI / AVKit / Foundation で作る）。Markdown描画も自前でよい（凝った描画は不要。段落と改行が読めれば十分）。
- Swift Package Manager 構成（`swift build` が通ること）。Xcodeプロジェクト必須にしない。

## 7. 仕上げ（必ず全部やる）

1. `swift build` を実行し、**出力をそのまま作業票へ貼る**。
2. `swift test` を実行し、**出力をそのまま作業票へ貼る**。
3. 実際にアプリを起動し、テストデータが3ペインで表示されることを確認する。**確認できた内容を具体的に書く**（何件表示されたか、写真が出たか等）。起動できなかった場合はその事実とエラーを貼る。
4. `docs/作業票/日記アプリ_フェーズ1.md` を作る（テンプレートは `docs/作業票テンプレート.md`）。次を必ず含める:
   - ビルド結果（実出力）
   - テスト結果（実出力）
   - 起動確認の内容
   - **「自分で決めたこと」**（仕様になかったので自分で判断した点の一覧）
   - **「試したが駄目だったこと」**（3回試して駄目だった件があれば）
   - 懸念・要確認
5. `ds/diary-viewer` ブランチへ push する。
6. **C層（別セッションレビュー）は省略してよい**（夜間の無人実行のため）。作業票にその旨を一行書く。A層（ビルド・テスト）は省略しない。

## 8. 完成の定義

- `swift build` が通る。
- `swift test` が通る（パーサーのテストを含む）。
- アプリが起動し、同梱テストデータが3ペインで表示され、エントリを選ぶと右に本文と画像が出る。
- 作業票が実出力つきで存在する。
- `ds/diary-viewer` ブランチへ push 済み。

**全部できたら、そこで終了してよい。追加の機能を勝手に作り足さない**（特に書き込み・編集機能は絶対に作らない）。

時間が余った場合は、機能を足すのではなく、**テストケースを増やす**ことに使う。
