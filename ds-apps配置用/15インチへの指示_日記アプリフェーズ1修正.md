前提: フェーズ1の実装は受け取り済み。**検品で実データ由来のバグが見つかったので直す。**

§0の「止まらないルール」は前回の作業票と同じものを引き続き適用する（質問して待たない／エラーは3回試して代替へ／自分で決めたことを記録）。

## 背景（なぜ直すか）

本人の**実際の日記データ**（13年・1,113エントリ）と突き合わせて検品した結果、**表示されずに消えるエントリがある**ことが確認された。テストが全部通っているのに起きる。理由は、**テスト用データに実データの特徴が入っていなかった**ため。

実データで確認した数字:

- 正しい日付見出し `## YYYY-MM-DD（曜）H:MM:SS` … **1,113件**（移行記録と完全一致。形式の想定は正しい）
- **日付形式ではない `## ` 見出し … 18行**（すべて `2024.md`）
  - 例: `## 今思ったなりたい人20241016の朝` / `## ↑を受けての昼の俺↓` / `## フィリピンのことで知りたいこと` / `## 第１週　１１・３−９` / `## ２（土）` `## ３（日)` …（週間予定を`## `で書いた塊がある）
- この結果、**2ブロック・162行が画面から消える**（2024.mdの全2,446行のうち約6.6%）

---

## バグ1【最優先】`## ` で始まる行を、日付を確認せずにエントリ開始とみなしている

### 現状のコード（`JournalParser.swift`）

```swift
private static func isEntryStart(_ line: String) -> Bool {
    guard line.hasPrefix("## ") else { return false }
    if line.hasPrefix("###") { return false }
    return true
}
```

### 何が起きるか

1. 本文中の `## 今思ったなりたい人20241016の朝` が**新しいエントリの始まり**と判定される。
2. そのブロックは `parseEntryBlock` で日付の正規表現に失敗し、`return nil`。
3. `compactMap` が nil を捨てるので、**その見出しから次の正しい日付見出しまでの本文が丸ごと消える**。
4. さらに、**直前の正しいエントリも、その位置で本文が途中で打ち切られる**。
5. 例外もエラーも出ない。`[パース警告]` が print されるだけで、画面上は「最初から無かった」ように見える。

### 直し方

**`isEntryStart` で日付形式まで確認する。** 日付見出しの正規表現（`entryHeadingPattern` と同じ形）に一致する行だけをエントリ開始とみなす。一致しない `## ` 行は**ただの本文として扱う**（本文に含めて表示する）。

`hasPrefix("###")` の行は不要（`hasPrefix("## ")` の時点で `### ` は既に除外されている）。消してよい。

### 受け入れ確認

- テストを追加する: **本文の途中に `## 今日のまとめ` のような日付でない見出しがあるエントリ**をfixtureに入れ、
  - そのエントリが**消えないこと**
  - `## 今日のまとめ` 以降の本文が**そのエントリの本文に含まれること**
  - エントリ総数が正しいこと
- 既存テスト `testMalformedHeading`（「スキップされる」ことを確認している）は、**期待している動作そのものが誤り**なので、上の新しい期待に書き換える。

## バグ2【フェーズ2の前に必ず】`---` を本文中で見るとfrontmatter扱いになる

### 現状のコード

```swift
if line.trimmingCharacters(in: .whitespaces).hasPrefix("---") && !inFrontmatter {
    inFrontmatter = true; continue
}
```

ファイルの**どこにあっても** `---` で始まる行が frontmatter の開始として扱われ、次の `---` まで**全部読み飛ばされる**。

現在の実データでは各ファイル `---` は2本（frontmatterのみ）なので**まだ発症していない**。ただしフェーズ2でWordから貼り付けた文に区切り線 `---` が入れば、そこから先が消える。

### 直し方

**frontmatterは「ファイルの先頭にある場合だけ」**とする。1行目が `---` のときだけ frontmatter モードに入り、その閉じ `---` を見つけたら、以降は二度と frontmatter 判定をしない。

### 受け入れ確認

- 本文の途中に `---` を含むfixtureを追加し、その前後の本文が両方とも保持されることをテストする。

## バグ3【軽い】日本語のタグに句読点が混ざる

`extractTags` の `[^\s#]+` は空白以外を全部拾うため、日本語では `#買い物。` や `#映画、` のように**句点・読点までタグ名に入る**（日本語は記号の前に空白を置かないため）。`#買い物` と `#買い物。` が別タグとして数えられる。

### 直し方

タグ名として取り込む文字を、句読点や括弧などの区切り記号の手前で止める。少なくとも `。、．，！？（）「」』】・…` と半角の `.,!?()[]{}:;"'` は含めない。

### 受け入れ確認

- `今日は映画を見た #映画。そのあと買い物 #買い物、疲れた` から `#映画` と `#買い物` の2つだけが取れることをテストする。

## バグ4【無害だが直す】目次行のスキップ条件が成立しない

```swift
if line.hasPrefix("# ") && pastFrontmatter && !pastTableOfContents {
    pastTableOfContents = true   // ← ここで true になる
    continue
}
if line.contains("[[_ジャーナル目次") && pastTableOfContents == false {  // ← 常に false
    continue
}
```

`# ジャーナル YYYY` を読んだ時点で `pastTableOfContents` が `true` になるため、その次に来る `[[_ジャーナル目次|← 目次]]` 行の条件は**永久に成立しない**。実害は無い（最初のエントリ見出しより前の行は結局捨てられるため）が、意図と動作が食い違っているので条件を直すか、素直に「最初のエントリ見出しより前は全部無視」に書き換える。

---

## この修正が重要な理由（必ず読むこと）

フェーズ1は**読むだけ**なので、これらのバグでファイルが壊れることはない。**画面に出ないだけ**で、元のMarkdownは無傷。

しかし**同じパーサーをフェーズ3（既存エントリの編集・書き戻し）でも使う**。そのとき、パーサーが取りこぼしたブロックを持たないまま書き戻せば、**162行はファイルから永久に消える**。13年分の日記は取り返しがつかない。

したがって、**バグ1と2は、書き込み機能を実装する前に必ず直っていること**。
