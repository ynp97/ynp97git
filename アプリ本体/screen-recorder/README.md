# スクトレル 1.5

macOS 15以降。メインディスプレイ全体、システム音声、既定のマイクを一緒に録画する個人用アプリ。
カメラ映像の追加、クラウドへの送信は行わない。会議アプリ内で表示されている自分の顔は、画面の一部としてそのまま映る。

## 使い方

1. `/Applications/ScreenRec.app` を開く。
2. 初回はmacOSの画面収録・マイクの権限を許可する。画面収録の許可後はアプリを終了して開き直す。
3. 必要なら「パソコンの音」「マイク（自分の声）」を調整する。0〜200%、100%が従来の標準、0%はミュート。設定は次回も保持。録画中にも変更できる（保存中は不可）。
4. 聞きながら調整するときはヘッドフォンを装着し、録画前に「ヘッドフォンでモニター」をON。通常はOFF。
5. 「録画を開始」→ メーターを見て音量調整 →「録画を停止」。
6. 「保存しました」が出たら「保存した動画を表示」で動画を開く。

保存先：初期値は `~/Desktop/ScreenRecordings/`。「保存先を選ぶ…」で変更でき、次回も記憶する。停止後に音声を合成するため、保存完了までアプリを終了しない。
複数ディスプレイの同時録画には対応していない。現在はmacOSのメインディスプレイを対象とする。
マイクはmacOSの既定入力を使用する。録画中の入力機器の切り替えは実機検証していない。

## 保存の仕組み

録画中はH.264映像と、システム音声・マイク音声の2トラックを `.source.mov` に保存。
停止後、元の時間位置を保って音声のみを合成し、映像を再圧縮せず1本の `.mov` にまとめる。
標準100%では各音量を0.5に設定し、200%では1.0にする。フェーダーの変更を録音中の音声へ即時反映する。パソコンのスピーカーや会議アプリの音量自体は変更しない。
最終動画の映像1本・音声1本・長さ・ファイルサイズを確認してから元ファイルを削除する。
合成失敗や録画異常の際は、復旧用の元ファイルを残す（0バイトだけ削除）。

## ビルド

`bash build.sh`

- 有効な `ScreenRec Local Development` または `Apple Development` 証明書が必要。
- ad-hoc署名へ自動で切り替えない。バンドルIDは `com.screenrecorder.app` を維持。
- 署名済みステージング版を検証してから `/Applications/ScreenRec.app` を置き換える。
- 起動中なら置き換えず停止する。既存アプリはバックアップして残す。
- 2026-09-06、このMacには証明書が無かったため `ScreenRec Local Development` を生成し、ログインキーチェーンへ登録。ユーザーのcodeSign用途に限定した信頼設定を追加。秘密鍵はキーチェーンに保存し、Vaultには置かない。
- `main.swift` は複数ファイル化に合わせて `App.swift` に改名した（SwiftPMのトップレベル入口との衝突回避）。

## 検証

`bash Tests/run-audio-check.sh`

4秒の映像と、440Hz・880Hzの二つの音声から実際の動画を生成する。
マイク役の880Hzは0.5秒遅く開始。最終音声をデコードして両周波数と時間位置を確認する。
不完全な音声構成を受け付けず、元ファイルが保持されることも検査する。

任意の実機テスト：アプリを終了後、次を実行する。通常起動で自動録画はしない。

```
open -a /Applications/ScreenRec.app --args --recording-check /private/tmp/screenrec-live-check.json
```

10秒録画し、結果を指定JSONへ保存する。OS権限を自動許可する機能は無い。
2026-09-06：本人の許可後に10秒の実機録画・保存に2回成功。元動画のシステム音声/マイク音声を各々PCMへデコードし、双方に音声信号を確認。最終動画は映像1＋音声1、311フレーム全てデコード成功。更新後の権限保持も確認。長時間会議・途中の入力機器切替・Mac再起動後は未検証。

検査モードは元の2音声トラックも残す。通常起動では最終MOVだけを残す。検査後はアプリを終了し、引数なしで開き直す。

2026-09-07：1.4の音量変更（標準・異なる比率・各入力のミュート）を最終MOVのデコード解析で確認。スライダー実操作と再起動後の95%/105%保持も確認。確認後は両方100%へ戻した。


## 1.5 ミキサーとモニター

- 2本のメーターは音量調整後の各入力を表示。緑・橙・赤で大きさを示す。合計ピークが大きい場合も注意を表示するが、自動で音割れを防ぐリミッターではない。
- 録画開始前は入力を収録せず、メーターも動かない。
- 録音とモニターへ同じ調整済みPCMを分岐。保存時は音声を再合成するので圧縮による差はある。
- モニターON時はAppleのCoreAudioプロセスタップを使用。元のパソコン音を一時的に抑えてミックス音を再生し、自アプリを取り込み対象から除いて二重録音を防ぐ。停止時にタップを破棄する。
- Mac本体の音量は聴く音の大きさ。録音バランスはアプリの2本のフェーダーで調整する。モニターOFFで普通に聞こえるパソコン音は、録音のミックスとは異なる。
- 自分の声にも再生の遅れがある。スピーカーでのマイクモニターは音が回るため、ヘッドフォンで使う。
- モニターON時、音声エンジンの接続変更を検出すると停止して保存する。長時間・機器切替の実機評価は今後必要。
- 1.4のソースは `Versions/1.4/` に保存。

実機検証（2026-09-07）：通常録画11秒とモニター付き58秒が保存され、映像302／1652フレームを全てデコード。モニター検証は本体スピーカー・マイク0%で実施。パソコン音100→50%の操作でメーター-32→-38dBを確認。ヘッドフォンで自分の声を聞いた際の遅延・聞き心地は本人確認待ち。

## App Store販売に向けた準備

本人は将来の販売を希望。今回の版は個人用の試作で、審査提出・配布はしていない。

- Apple公開APIのみで録画・音声処理。録画開始／停止とタイマーを明示し、OSの収録権限を使用。音声・映像はローカル保存。
- 保存先選択とsecurity-scoped bookmarkを実装。`SCREENREC_SANDBOX=1 bash build.sh` でsandbox用entitlementsを付ける準備はあるが、このモードの実機検証は未実施。通常の個人用ビルドはsandboxなし。
- 販売前にはsandbox下の画面・音声タップ・保存・再起動を検証し、長時間会議、音ズレ、ヘッドフォン遅延、切断／スリープ復帰を確認する。
- Appleの配布署名とプロビジョニング、App Store Connect設定、プライバシー情報・サポート情報・商品説明・価格の準備が必要。現在の自己署名証明書はストア配布用ではない。
- 審査可否は未確定。公式確認先：[App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/)（2.4.5 sandbox、2.5.14録画の同意と明示）。
