# 既存日記の永続ID対応（2026-09-08・Codex）

本人の「app97 日記の続き。引き継ぎから再開して。次は既存日記の永続ID対応。」「やって。」を受け実装。

## 実装

- 0.5.0/build 5。DiaryCoreの`JournalIdentity`と、SQLite schema 4の`journal_identity`対応表を追加。schema 1/2/3から更新する。旧アプリはschema 4を拒否するため、DBだけ旧バージョンへ戻さない。
- 対応表は年別ファイル名・全体ハッシュ・各ブロックのUUID／原文ハッシュ／明示IDの有無を保持。文章の正本はMarkdown。本文や既存Day Oneコメントは変更しない。
- 全年を読み終えてパース成功後、対応表を一つのSQLiteトランザクションで確定。保存ロックと同期設定はCaptureLibraryを共用。バックアップのSQLiteコピーにも対応表が含まれる。
- 明示IDはそのまま使い、全年にまたがる重複を拒否する。IDなしの一意な原文は並べ替え・ファイル移動後も同じID。同一原文が複数ある場合は、ファイル全体が不変の場合だけ位置で識別する。
- 旧原文の消失と新原文の出現が同時なら、本文・日付の外部訂正か削除＋追加か断定できないため、台帳更新と一覧表示を停止する。同文重複があるファイルの変更も保守的に停止。前の対応表は残す。
- 通常ライブラリへの書込開放は前回どおり行わない。**今回の永続ID対応表の自動作成・利用も、専用command＋架空データ印のあるライブラリだけに接続した。通常閲覧のIDなしEntryは従来どおりであり、本番へ適用済みとは言わない。**
