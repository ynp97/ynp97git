## 重点

1. 保存ごとの全体バックアップを除去し、変更対象の本文とpendingだけで従来の中断回復を維持できるか。操作本文の蓄積・世代管理は引き続き未実装と明記してある。
2. readOnly接続と通常閲覧でDB・原文・writer.lockを変更しないか。allowJournalWrites=falseとの違い。
3. schemaの列構成・型・主キー等の照合、明示した旧版退避の完成前に移行を進めないか。版1〜4は合成fixtureであり、過去版実物を検証したとは扱わない。
4. adoptionsとjournal_changesのpendingを対称に停止し、原文点検と救出退避ができるか。通常の完了版バックアップと救出用を混同しないか。
5. journal/ジャーナルの一貫した選択、二重系統の拒否、0444/uchg媒体、errnoとディレクトリ同期。
6. 保存失敗直後の画面でも点検と救出へ移れるか。0.7.0はOSパネルを使わず、アプリ内の退避先フォルダ欄へ絶対パス/ホーム省略を指定する方式。実機でOSパネルが確定できなかったため取り除いた。
